## Design Specificity Verdict

**LLM assessment:** the shell is category-interchangeable — Gravity UI plus the default editor toolbar; any editor could use it unchanged. Composition: two stacked toolbars (11 + ~20 controls = 31 before the text), then full-width text with no column, no document identity. IA is organised by file extension rather than by task ("MD MD MD DOCX DOCX XLSX"). The only authored elements are the solarized token remap and `line-height: 1.2`; "GravityMD" exists only in a three-line About dialog and the OS title. Missed character: the on-disk file (no path, no "opened from Explorer", no recent), the dual WYSIWYG↔markup engine (one unnamed `</>` glyph among 20 icons), YFM→pipe normalisation and GOST DOCX margins (visible only in a warning toast).

**Deterministic scan:** `impeccable detect --json src` → exit 0, `[]` — zero findings, zero advisories, nothing suppressed (no config, no DESIGN.md, no disable comments). A sensitivity probe outside the project proved the engine is live (`overused-font` advisory fired), but its rule set is marketing/web-aesthetic oriented and does not test focus, tab order, ARIA names, contrast, or overflow. "Clean" here is not a quality signal for this Operate surface; it coexists with the measured defects below.

**Visual overlays:** none injected — the detector ran as a CLI scan and the surface was measured directly on the real WebView2 instance through CDP (evidence: numbers and screenshots 10–12), so no `[Human]` overlay tab exists for this run.

## Overall Impression

Strong technical base and a pleasant editor under a weak shell. The "type and save" path works and looks tidy; what is missing is everything that makes a desktop tool feel trustworthy: document identity, task-language actions, keyboard layer, and data-loss guardrails beyond the close button. Biggest single opportunity: give the document a status bar and make the file cluster speak verbs — that alone lifts heuristics 1, 2, 6, 7, 8.

## What's Working

1. **Zero chrome on start** — no login, account, tabs, or forced onboarding; the app opens into a document with the caret ready (`autofocus`). Right posture, and rare.
2. **The unsaved-changes dialog is proper desktop craft** — filename in quotes, three unambiguous buttons, correct hierarchy, honest copy. The only place where the copy truly works.
3. **Technical depth tuned to the persona** — dual engine, KaTeX, Mermaid, YFM→pipe normalisation, DOCX with GOST margins; solarized is a real full-token remap, portals included.

## Priority Issues

**[P0] Silent work loss on Open / Import / Explorer handoff.** Why it matters: close is guarded, but three other ways to replace the document are not — including the showcase scenario (double-click a `.md` while the app runs). Edits vanish with no dialog and no undo. Fix: one `confirmDiscard()` shared by close/open/import/file-open; for DOCX offer "Replace document / Insert at cursor"; after replacement a toast action "Restore previous document". Suggested command: /impeccable harden

**[P1] Toolbar speaks formats; three buttons are named "MD".** Why it matters: the very first step (open a file) needs three hovers; "MD" reads as a format chip next to DOCX/XLSX. AX tree confirms duplicate names (MD ×3, DOCX ×2). Fix: verb cluster — "Open…", "Save" (with a dirty dot), "Save As…" in overflow; conversions folded into "Import ▾ / Export ▾"; theme and About in a right-hand utility cluster; zoom into the status bar. Suggested command: /impeccable clarify

**[P1] No document identity and no status.** Why it matters: no filename, path, changed-marker (beyond a hijacked danger-red), word count, or caret position; the lower half of the window is dead space. Fix: a 28 px status bar — `Q3 Release Notes.md · ~/Notes` | `Unsaved changes / Saved 2s ago` | `412 words · 1 840 chars · WYSIWYG`; plus a dot in the OS title. Suggested command: /impeccable layout

**[P1] No keyboard layer and no native menu.** Why it matters: Ctrl+S/O/N do nothing app-wide; macOS has no menu bar (no Quit, About, Preferences); keyboard users cannot reach the toolbar from the editor at all (trapped) and the editor shell gets focus with no visible indicator. Fix: accelerators (⌘/Ctrl+S, ⇧S, O, N, E, T, ±), a `?` shortcuts screen, minimal native menu; restore a visible focus ring on the editor shell (WCAG 2.4.11). Suggested command: /impeccable audit

**[P2] Theme and About are guess-buttons.** Why it matters: one click cycles three themes; the icon shows the current state; the tooltip is the raw value "dark"; About is three lines with no shortcuts, updates, or changelog. Fix: popover with three named theme rows and swatches (minimum: "Theme: Dark — switch to Light"); About as the product's character home: icon, one-line positioning, version+build, "Keyboard shortcuts", "Check for updates", "Changelog", "License". Suggested command: /impeccable polish

## Persona Red Flags

**Alex (power user):** no Ctrl+S/O/N, no menu; no recent files — every session starts with a native dialog; zoom only by dragging an 80 px slider (no keyboard, no click on "100%"); theme needs a click-and-look; opening a file costs three hovers over "MD"; file path shown nowhere (cannot copy or verify); no focus mode, no command palette. Will leave for Obsidian/VS Code.

**Jordan (first-timer):** cannot tell which of three "MD" opens a file (tooltip arrives after ~1 s; folder/floppy/file-up icons read as three saves); the starter text looks like an already-open file, so the first instinct is to edit "Welcome"; `</>` means nothing; the sun reads as brightness, not theme; a red button reads as "something broke"; `M`, `A̅`, shield are unnamed; About offers neither help nor shortcuts.

**Riley (stress tester):** edits → Open → edits gone; DOCX over the note → replaced, no undo, file becomes Untitled; double-click another `.md` → first document silently replaced; export within 300 ms of typing → potentially stale file; 500-row XLSX appended at the end with no position feedback; read-only folder → `FS_WRITE_DENIED` in the toast; crash → no draft, no "restore last session".

## Minor Observations

- At the shipped default window 800×600 the About button is clipped by the right edge (28 px button, 11 px visible; toolbar scrollWidth 817 vs clientWidth 800, `nowrap`, body `overflow: hidden`). The bar is wider than its own default window.
- Zoom is CSS `zoom` on text only: the toolbar stays put (good), but line measure grows to ~1 900 px; at 200% reading gets harder, not easier; at no width is there a column or max measure (≈140 chars at 1280).
- `line-height: 1.2 !important` plus 12 px spacing makes a wall of text; at 200% H1 ≈ 64 px vs 30 px body — hierarchy drifts.
- In the rail, `{ }` (code) and `</>` (mode switch) sit adjacent: two "programmer" glyphs, one changes the whole editing model.
- Error copy exposes IPC codes (`FS_*:`).
- The placeholder is saveable: the first Save writes the welcome text into a new file.
- Dirty state is colour-only (no ARIA change, no live-region announcement); its red fails 4.5:1 in all three themes (2.89 dark / 4.14 light / 3.77 solarized).
- Focus ring contrast to toolbar background: 2.41 dark / 2.60 light (fails 1.4.11 3:1), 3.57 solarized (passes).
- `.zoom-value` "100%" contrast: 4.36 dark / 3.89 light / 3.64 solarized — fails AA everywhere.
- `prefers-reduced-motion`: library chrome respects it (13 media rules), the app's own slider transition (100 ms) does not.

## Questions to Consider

- If the bar said "Open · Save · Export" instead of "MD · MD · MD · DOCX · DOCX · XLSX", what would the app no longer need to hide?
- Why does a desktop editor say less about its file than a web form says about its fields?
- The real differentiators (YFM→pipe on save, GOST DOCX, two engines) are invisible until something breaks. What if one of them were the first thing a new user saw instead of the "Welcome" paragraph?
